# GM31_prroject2

Visual Studio / C++20 / DirectX 11 で開発している、共通ゲームエンジンと4つのアプリケーションのプロジェクトです。

| プロジェクト | 内容 |
|---|---|
| Engine | 描画、入力、音声、シーン・オブジェクト管理、衝突判定、モデル・アニメーション、リソース管理を提供する共通の静的ライブラリ |
| WireAction | おもちゃロボが300mの工場をワイヤーで登る、一人用タイムアタック「TOY WIRE / SKY RACE」 |
| BattingCenter | 共通Engineを使う独立したバッティングゲーム |
| ClassroomWalk | キャラクターの移動・アニメーション、地形や水面などを扱う授業用サンプル |
| ShaderGallery | シェーダー、照明、材質、画面効果を比較・調整する授業用アプリ |

各アプリは `Engine.lib` を参照し、固有のゲーム処理と実行時アセットをそれぞれのプロジェクトで管理します。
構成と開発上のルールは [PROJECT_STRUCTURE.md](PROJECT_STRUCTURE.md)、
授業用アプリの詳細は [CLASSROOM_WALK.md](CLASSROOM_WALK.md) と [SHADER_GALLERY.md](SHADER_GALLERY.md) を参照してください。
キャラクターアニメーションのブレンドツリー・攻撃モーションの重ね方は [ANIMATION.md](ANIMATION.md) にまとめています。

## TOY WIRE / SKY RACE

主作品のWireActionでは、ワイヤーの振り子運動、ジャンプ、壁蹴り、ダッシュを組み合わせて頂上を目指します。
外周の足場を経由するルートと中央の近道があり、クリアタイムと自己ベストを比較できます。
現在のレースには敵ドローンとHPもあり、敵を避けながら登ります。

## 遊び方

- タイトルで Enter：レース。T：練習場。
- WASD：移動。Space：ジャンプ／壁蹴り。
- マウス：視点。左クリック長押し：即ワイヤー接続。離す：解除。
- ワイヤー中に移動入力で振り子を加速し、上昇中に解除すると高く飛べます。
- Shift＋移動：空中ダッシュ。接続・着地・壁蹴りで回復します。
- R：最下部からリトライ。Tab：ポーズ。Esc：ゲーム終了。
- 結果画面の R：再走。Enter：タイトル。Esc：ゲーム終了。

現在は共通のウィンドウ処理がEscで終了するため、レース中もEscはゲーム終了になります。
画面内に残っている「Esc タイトル」の案内とは挙動が異なります。

移動・ジャンプ・ワイヤーの最初の操作から計測し、頂上のチェッカーゲートへ入るとゴール。
タイムは「分:秒.百分の一秒」で表示し、ゴールした走行のタイムを自己ベストと比較します。

### 敵・HP・ゲームオーバー

50mごとの大きな踊り場には敵ドローンを配置しています。現在の設定では各踊り場に2体、
プレイヤーの最大HPは3です。敵は近づくと追跡し、攻撃範囲内でダメージを与えます。
HPが0になるとゲームオーバーになり、結果画面に死亡時の高度を表示します。
ゲームオーバーの走行は自己ベストに保存しません。

左クリックはワイヤー操作に使い、プレイヤーの剣攻撃は実行しません。
剣や旧ミッションに関連するコード・設定はリポジトリに残っていますが、現在のレースのクリア条件は頂上への到達です。

## ワイヤーの巻き付き

ワイヤーは足場を貫通せず、角に当たるとそこで折れます。折れた角が新しい支点になるので、
振り子の半径が縮んで角速度が上がります。梁や支柱の角にわざと引っ掛けて加速できます。

- 経路は「アンカー → 折れ点… → プレイヤー」の折れ線です(`wireRopePath.*`)。
- プレイヤー側の区間が箱を貫いたら、前フレームからの移動で最初にまたいだ辺を求めて折れ点を置きます。
  区間が掃いた範囲は三角形(支点・前の位置・今の位置)になるので、箱の12本の辺とこの三角形の交差を調べます。
- 折れ点は辺の上を滑ります。辺を軸に2つの面を平らに展開したとき、前後の点を結ぶ直線が辺と交わる位置です。
- 箱は凸なので、折れ点の前後を真っ直ぐ結んで箱に触れなければ、その折れ点を外します。
- 巻き付きは2cm以上の貫通で始まり、解除は箱を2cm膨らませた判定で行います。境目で振動しません。
- 折れ点は箱と辺の番号で持ち、位置は毎フレーム取り直すので、動く足場にも追従します。
- 足場は箱を重ねて作っているので、隣の箱の内側に入る辺は折れ点の候補から外します。

見た目のロープ(`wireRopeVisual.h`)は移動の計算とは別です。支点から手までを14個の質点で結び、
Verlet積分と距離拘束で、余った長さのたるみと揺れを出します。

物理として正しい部分と、操作感のために残した部分は次のとおりです。

| 項目 | 扱い |
|---|---|
| 角での折れ・解除、巻き付きによる半径の短縮 | 幾何として正確に計算 |
| アンカー方向へ常に引く加速度、解除時のブースト | 操作感のための演出。実際のロープには無い力 |
| 接続の瞬間 | 入力の同フレームで成立。フックが伸びるのは見た目だけ(最大0.1秒) |
| ロープのたるみ | 見た目だけ。たるんだロープは足場に当たらない |

`assets/config/wire-gameplay.cfg` で切り替えられます。

- `wire.grapple.wrap_enabled=0`: 巻き付きを切り、足場を貫通する直線に戻します。
- `wire.grapple.rigid_rope=1`: 伸びないロープとして扱います(実験用)。牽引とバネを使わず、
  たるんでいる間は引きません。`wire.grapple.reel_speed` が巻き取りの速さです。

F1のデバッグ表示に、折れ点の数と支点までの残りの長さを出しています。

## ルート

水色の足場は12.5m刻みの外周ルート。大きな足場を経由して着実に登れます。
オレンジの中央クレーンは40m刻みの近道。解除のタイミングと空中の刺し直しで外周を短縮できます。
昇降台や動く吊り箱も、乗ったりワイヤーを掛けたりできます。

50mごとの黄緑の踊り場に着地すると復帰地点を保存します。
落下中もワイヤーを使え、途中の足場に着地できます。コース下へ落ち切った場合だけ復帰地点へ戻ります。
落下からの復帰時にもタイムは止まりません。HPは回復しません。
Rでリトライすると最下部から新しい走行を開始し、タイムとHPをリセットします。

自己ベストは `%LOCALAPPDATA%/ToyWireRace/tower-v1.txt` に保存します。
デバッグの時間倍率・無敵・コマ送りを使った走行は記録対象外です。
コース変更時には `WireRace::CourseVersion` と保存ファイル名を更新して記録を分離します。

## 開発

Visual Studioで `GM31_prroject2.slnx` を開き、WireActionを起動プロジェクトにします。
BattingCenter、ClassroomWalk、ShaderGalleryを試す場合は、それぞれを起動プロジェクトにします。
WindowsとDirectX 11を利用できる実行環境、Visual StudioのC++開発環境が必要です。

授業用シェーダー比較は `ShaderGallery` を起動します。SP31の授業用操作を
GM31の共通Engineから試せます。操作と移植構成は `SHADER_GALLERY.md` を参照してください。

Developer PowerShell:

```powershell
msbuild GM31_prroject2.slnx /p:Configuration=Debug /p:Platform=x64 /m
bin\x64\Debug\WireAction\WireAction.exe --self-test
bin\x64\Debug\BattingCenter\BattingCenter.exe --self-test
bin\x64\Debug\ClassroomWalk\ClassroomWalk.exe --self-test
bin\x64\Debug\ShaderGallery\ShaderGallery.exe --self-test
```

自己テストは共通の音声アセットがあるリポジトリ直下から実行してください。
WireActionではエンジンのテストに加え、時計・ゴール交差・振り子・慣性・落下判定を検証します。
ワイヤーの巻き付きは、角での折れと解除、柱への2周の巻き付けと巻き戻し、動く足場への追従、
重なった箱の中を不規則に飛び回る約2万フレームで経路が形状を貫かないことを数値で確認します。
`self-test-race.log` に各項目の結果を出します。

```powershell
bin\x64\Debug\WireAction\WireAction.exe --render-test
```

描画テストは非表示のウィンドウで実際のDirectX描画と画面遷移を実行し、実行ファイルの隣に
`race-*.png` と `render-test-race.log` を保存して終了します。GPUとWindowsの描画環境が必要です。
`race-wire.png` は、クレーンの支柱の向こう側へ接続して角で折れたワイヤーの描画です。

移動・ワイヤー・敵・HPの調整は `assets/config/wire-gameplay.cfg`、音量・マウス感度の設定は `assets/config/wire.cfg`。
設定やアセットを変更した後は再ビルドして、実行フォルダーへ反映してください。

### 見た目の回帰チェック

エンジンを変更したときに描画結果が変わっていないかを、ピクセル単位で確認できます。
ビルド、self-test、境界検証、WireAction と ClassroomWalk のレンダーテストを実行し、
出力されたPNG画像と描画テストのログ2本をベースラインと比較します。

```powershell
# 変更前の正しい状態で一度だけ(ベースラインを artifacts/render-baseline に保存。約100MB、git管理外)
powershell -ExecutionPolicy Bypass -File scripts\verify-render-regression.ps1 -UpdateBaseline
# 変更後に毎回
powershell -ExecutionPolicy Bypass -File scripts\verify-render-regression.ps1
```

ClassroomWalk の左上には実時間の FPS 表示があって毎回変わるため、その領域(760×48)は比較から除外しています。
意図して見た目を変えた場合は、確認したうえで `-UpdateBaseline` で撮り直してください。
`wireRace.h` は描画と入力から独立したレース状態、`wireSwingPhysics.h` は数値検証可能なワイヤー物理です。

## 次のプレイテストで見ること

1. 初見でも水色の次の足場を見つけられるか。
2. 上昇中の解除を覚えたとき、明確に到達高度とタイムが変わるか。
3. 落下後にアンカーを見つけて復帰できるか。
4. 再走時に「次はこの足場を飛ばす」という狙いが生まれるか。
5. 踊り場の敵を認識でき、HP・被ダメージ・ゲームオーバーの理由が伝わるか。

現段階の物理・コースは最初のプレイ可能な調整です。数値テストと描画テストだけでは面白さや
初見難易度は確定しないため、実プレイで足場間隔・カメラ・加速量を詰めます。
ゴースト・オンラインランキング・同時対戦は未実装です。

## FpsGame の操作

`FpsGame.vcxproj` は一人称の射撃練習用プロジェクトです。WASDで移動、マウスで視点操作、Shiftでダッシュ、Spaceでジャンプ、左クリック長押しで連射、Rでリスタートします。

右クリックを押している間はエイムします。約0.2秒かけてカメラが照準位置へ移動し、視野角が75度から60度へ変化します。銃も中央へ構え、歩行時の揺れを抑えます。右クリックを離すと滑らかに通常の構えへ戻り、切り替え途中で押し直すこともできます。
## SlowAction の操作 (時間減速アクション試作 v0.1)

`SlowAction.vcxproj` は、時間減速・ダッシュ・吹き飛ばし・空中追撃の組み合わせを確かめるための試作です。

| 入力 | 動作 |
|---|---|
| WASD | カメラ基準の移動 |
| マウス | カメラ回転 |
| Shift 長押し | ダッシュ (方向転換に軽い慣性) |
| 左クリック 短押し / 長押し | 離した瞬間に通常攻撃 / 強攻撃 (0.25秒以上で強。強は出が遅く隙が長く、途中まではダッシュで抜けられない) |
| 右クリック 長押し | 時間減速 (敵側だけ0.35倍。ゲージを消費。敵の攻撃が当たる直前に発動するとジャスト減速になり、ゲージ回復と得点) |
| R / F1 / F2 / Esc | やり直し / 当たり判定表示 / 敵無敵(練習用) / 終了 |

通常攻撃は大剣の3段コンボです。攻撃の終わり際に次を押す(先行入力)か、終わってから0.3秒以内に押すと次の段へつながり、3段目は当たった敵を小さく吹き飛ばします(強攻撃より近く・低く・短い)。強攻撃・ダッシュ・猶予切れで1段目に戻ります。各段のクリップ上の区間と当たる瞬間は `assets/config/slow-gameplay.cfg` の `Combo*` で調整できます。

左クリックを0.25秒押し続けると溜めに入り、回転斬りの構えでその場に止まります。溜めている間は移動もダッシュもできず、向きだけ変えられます。離すと強攻撃が出ます。

強攻撃は体ごと1回転する横薙ぎ(`Akai_Strong.fbx`)で、クリップ上の区間・当たる瞬間・再生倍率は `StrongClip*` と `StrongPlaybackSpeed` で調整できます。

強攻撃で敵を吹き飛ばし、着地する前にもう一度当てると追撃になります。3段目で浮いた敵にも追撃できます。追撃はダメージが1多く、地上で殴り続けるより早く倒せます。追撃すると吹き飛び時間と壁反射回数が戻り、時間減速ゲージが回復します(減速中の回復は減速終了時にまとめて反映)。

敵は3種類です。シーンファイルでは `int Kind` (0〜2) で指定します。

| 型 | 色 | 特徴 |
|---|---|---|
| 近接 (0) | 人型(Mixamo) | 近づいて殴る。予兆(赤く光る)の間に横へ動けば避けられる。歩き・のけぞり(通常攻撃)・殴られて浮いて倒れる(吹き飛ばしと撃破)のモーション付き。吹き飛ばすと背中から落ちて、受け身の後に起き上がる。倒すと亡骸が倒れてから床へ沈む |
| 射撃 (1) | 紫 | 6〜12m の距離を保ち、照準線を出してから撃つ。弾は攻撃で打ち返せ、撃った敵へ戻って吹き飛ばす |
| 重量 (2) | 灰 | 通常攻撃ではひるまない。強攻撃2回で装甲が割れて打ち上がる(飛ぶ距離は短い)。殴りかかってくる予兆中に強攻撃を合わせると一撃で割れる |

当てるたびにコンボが伸び、5コンボごとに得点倍率が上がります(最大4倍)。最後のヒットから2.5秒(ワールド時間なので減速中は長くなる)で切れ、被弾でも切れます。
追撃・壁反射・打ち返し・撃破は大きく加点され、右上に表示されます。最高スコアと最大コンボはやり直しても残ります(アプリを終了すると消えます)。

ヒットストップ・画面揺れ・被弾した敵の白い点滅・効果音は、当たりの重さに合わせて段階的に強くなります。
効果音は `scripts/generate-slow-action-sounds.ps1`、モデルは `scripts/generate-slow-action-models.sh` で生成した仮素材です。

### 編集モード (F3)

F3 でゲームを止めて編集モードに入り、もう一度 F3 でその配置のまま再生に戻ります。

- 視点: 右ドラッグで見回す、WASD / Q・E で移動(Shift で加速)、ホイールで前後。
- 選択: 「階層」の一覧か、画面上の点をクリック。
- 編集: 「インスペクタ」で名前・位置・回転・スケール・各オブジェクトの公開値を変更。追加・複製・削除は「階層」から。
- 保存: 「保存」を押したときだけ `assets/scene/slow-stage.scene` へ書きます(ソース側と実行フォルダの両方)。保存せずに再生へ戻った変更は、アプリを終了すると消えます。

ステージの配置(床・壁・障害物・プレイヤー・敵)はこのシーンファイルが持っています。テキストなので直接書き換えることもできます。
新しい型を編集対象にするには、`GameObject::Reflect` で値を公開し、`Engine::ObjectTypeRegistry::Register` で登録します。

調整値は `assets/config/slow-gameplay.cfg` にまとめてあり、再コンパイルなしで変えられます(意味は `include/slowActionTuning.h`)。
`SlowAction.exe --render-test` は仕様の数値と状態遷移を自動で確かめ、結果を `render-test-slow.log` と `slow-render*.png` に残します。

## 森の描画デモ（第一段階）

ShaderGalleryを --forest 付きで起動すると、GPUで揺れる草、密度LOD、視錐台カリング、自由カメラ、CPU/GPU計測を試せます。操作と検証方法は [FOREST_DEMO.md](FOREST_DEMO.md) を参照してください。木は仮形状で、写実表現は今後の段階です。
